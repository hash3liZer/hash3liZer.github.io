1b:T809a,<h2 id="introduction"><a href="#introduction">Introduction</a></h2>
<p>Hi, its been a while since i wrote something on my blog. Today, i am going to write about the process of deployment of a django application on a Ubuntu 22.02 live server. I'll try to cover as much details as i can and mention about the common issues i normally faces while following the process. This article is also a kind of reminder for myself for the tutorials and blog that i followed and the issues i ran into. So, we are going to cover this deployment process through <strong>Gunicorn</strong>, <strong>NGINX</strong> and optionally using <strong>Postgresql</strong> database.</p>
<h2 id="tutorial"><a href="#tutorial">Tutorial</a></h2>
<p>So, without wasting any further time. Lets jump right into the details.</p>
<h3 id="pre-reqs"><a href="#pre-reqs">Pre-Reqs</a></h3>
<p>The foremost thing are the pre-reqs that we need to follow this tutorial. First is a server with a public IP. Many of you who are reading this might already have one before moving one. Well, if you don't you can simply get one from any of the hosting services or Cloud platforms. Personally, i use <strong>DigitalOcean</strong> or <strong>AWS</strong> most of the time. And also, for the sake of this tutorial i'll be using a <code>t2.micro</code> instance of EC2 service from AWS.</p>
<p>But in general what you need is an online server with <strong>Ubuntu 22.04</strong> installed and with publicly accessibly ports. Thi should also work just fine with Ubuntu 20.04. Let me know in comments if someone tests it.</p>

<p>After this, we need to setup a <code>static</code> and <code>media</code> directory where our project static files are going to be stored. The <code>media</code> folder will contain files that are supposed to be uploaded by the user of the application. So, again in the <code>settings.py</code> file, move at the end of the file and find the line <code>STATIC_URL = 'static/'</code> and add some new content below it:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">...</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#79C0FF">STATIC_URL</span><span style="color:#FF7B72"> =</span><span style="color:#A5D6FF"> 'static/'</span></span>
<span data-line=""><span style="color:#79C0FF">STATIC_ROOT</span><span style="color:#FF7B72"> =</span><span style="color:#79C0FF"> BASE_DIR</span><span style="color:#FF7B72"> /</span><span style="color:#A5D6FF"> 'public'</span></span>
<span data-line=""><span style="color:#79C0FF">MEDIA_URL</span><span style="color:#FF7B72">  =</span><span style="color:#A5D6FF"> 'media/'</span></span>
<span data-line=""><span style="color:#79C0FF">MEDIA_ROOT</span><span style="color:#FF7B72"> =</span><span style="color:#79C0FF"> BASE_DIR</span><span style="color:#FF7B72"> /</span><span style="color:#A5D6FF"> 'media'</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#79C0FF">...</span></span></code></pre></figure>
<p>The <code>STATIC_ROOT</code> defines the folder where the public content like <em>css,js or imgs</em> are going to be stored upon running the <code>collectstatic</code> command on <code>manage.py</code> file. Please note that its totally different from the <code>STATICFILES_DIRS</code> variable which is used to define the directories to locate static files. Think of <code>STATIC_ROOT</code> as more of a <strong>production</strong> specific variable.</p>
<h3 id="spin-up-the-project"><a href="#spin-up-the-project">Spin up the Project</a></h3>
<p>Lets move towards spinning up the project for the public. For that, we will do the normal django commands like migrations and super user.</p>
<p>Run migrations and create a superuser:</p>
<pre><code>python3 manage.py makemigrations
python3 manage.py migrate
python3 manage.py createsuperuser     # Enter your credentials for the superuser when prompted
</code></pre>
<p><img src="/blog/img/47babf413c45.png" alt="image"></p>
<p>After this, we will run the <code>collectstatic</code> command to locate all the static files we have in our project and put them to the folder that we defined at <code>STATIC_ROOT</code> variable. These static files will be served by the <code>nginx</code> server and not from django like we see during the development.</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">python3 manage.py collectstatic</span></span></code></pre></figure>
<p><img src="/blog/img/e4d736406ecb.png" alt="image"></p>
<p>You can now execute the <code>runserver</code> command on public interface to see your website. Before also make sure nginx is not using the port <code>80</code> by default:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">service nginx stop</span></span>
<span data-line=""><span style="color:#E6EDF3">python3 manage.py runserver </span><span style="color:#79C0FF">0.0</span><span style="color:#E6EDF3">.0.0:</span><span style="color:#79C0FF">80</span></span></code></pre></figure>
<p>Now, if you access your website at port <code>80</code> you would be able to see your project:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">http:</span><span style="color:#FF7B72">//</span><span style="color:#79C0FF">PUBLCI_IP_ADDRESS</span></span></code></pre></figure>
<p><img src="/blog/img/968ae851ba9a.png" alt="image"></p>
<p>Finally, back in the <code>settings.py</code> put the <code>DEBUG</code> value to <code>False</code>. You can keep it enabled if you are going to debug the project or facing some other issue. But make sure to put the value to <code>False</code> for the production cases:</p>
<pre><code>nano myweb/settings.py

...
DEBUG = False
...
</code></pre>
<p>At this point, we have our project all ok. But this is not how we are going to host the website actually.</p>
<h3 id="setting-up-gunicorn"><a href="#setting-up-gunicorn">Setting up Gunicorn</a></h3>
<p>Gunicorn is the server service that we are going to configure with <code>nginx</code> for the public. We will configure a new <code>systemd</code> service for this. But before, we will test if <code>gunicorn</code> is really working or not. So, simply bind gunicorn to the <code>0.0.0.0</code> and test if we can access the website at port <code>80</code> like we did before. Note that we are still inside <code>/var/www/myweb</code> directory</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">gunicorn</span><span style="color:#79C0FF"> --bind</span><span style="color:#A5D6FF"> 0.0.0.0:80</span><span style="color:#A5D6FF"> myweb.wsgi</span></span></code></pre></figure>
<p><img src="/blog/img/f6f18fd86e0e.png" alt="image"></p>
<p>Fire up <code>nano</code> again for the gunicorn service and do the configuration:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">nano</span><span style="color:#A5D6FF"> /etc/systemd/system/gunicorn.service</span></span></code></pre></figure>
<p>Inside the file. I'll not get into much details of what is happening here. But you can refer to the <code>systemd</code> documentation for more in depth detail. However, we will review the <code>Service</code> section here:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">[Unit]</span></span>

<span data-line=""><span style="color:#E6EDF3">[Service]</span></span>
<span data-line=""><span style="color:#E6EDF3">User</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">www</span><span style="color:#FF7B72">-</span><span style="color:#E6EDF3">data</span></span>
<span data-line=""><span style="color:#E6EDF3">Group</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">www</span><span style="color:#FF7B72">-</span><span style="color:#E6EDF3">data</span></span>

<h3 id="setting-up-nginx"><a href="#setting-up-nginx">Setting UP NGINX</a></h3>
<p>This is the last step. We will configure <code>nginx</code> which in short is the public server and will take requests from the public and forward it to gunicorn as a reverse proxy. Remove the default enabled nginx website and create a new <code>nginx</code> project file:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">rm</span><span style="color:#A5D6FF"> /etc/nginx/sites-enabled/default</span></span>
<span data-line=""><span style="color:#FFA657">nano</span><span style="color:#A5D6FF"> /etc/nginx/sites-available/myweb</span></span></code></pre></figure>
<p>Inside the file, configure your web server:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="nginx" data-theme="github-dark-default"><code data-language="nginx" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">server</span><span style="color:#E6EDF3"> {</span></span>
<span data-line=""><span style="color:#FF7B72">    listen </span><span style="color:#79C0FF">80</span><span style="color:#E6EDF3">;</span></span>
<span data-line=""><span style="color:#FF7B72">    server_name </span><span style="color:#E6EDF3">DOMAIN_OR_PUBLIC_IP;</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#FF7B72">    location</span><span style="color:#FF7B72"> =</span><span style="color:#A5D6FF"> /favicon.ico </span><span style="color:#E6EDF3">{</span><span style="color:#FF7B72"> access_log </span><span style="color:#79C0FF">off</span><span style="color:#E6EDF3">;</span><span style="color:#FF7B72"> log_not_found </span><span style="color:#79C0FF">off</span><span style="color:#E6EDF3">; }</span></span>
<span data-line=""><span style="color:#FF7B72">    location</span><span style="color:#FFA657"> /static/ </span><span style="color:#E6EDF3">{</span></span>
<span data-line=""><span style="color:#FF7B72">        alias </span><span style="color:#E6EDF3">/var/www/myweb/public/;</span></span>
<span data-line=""><span style="color:#FF7B72">        add_header </span><span style="color:#E6EDF3">Strict-Transport-Security </span><span style="color:#A5D6FF">"max-age=31536000; includeSubDomains"</span><span style="color:#E6EDF3"> always;</span></span>
<span data-line=""><span style="color:#E6EDF3">    }</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#FF7B72">    location</span><span style="color:#FFA657"> /media/ </span><span style="color:#E6EDF3">{</span></span>
<span data-line=""><span style="color:#FF7B72">        alias </span><span style="color:#E6EDF3">/var/www/myweb/media/;</span></span>
<span data-line=""><span style="color:#E6EDF3">    }</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#FF7B72">    location</span><span style="color:#FFA657"> / </span><span style="color:#E6EDF3">{</span></span>
<span data-line=""><span style="color:#FF7B72">        include </span><span style="color:#E6EDF3">proxy_params;</span></span>
<span data-line=""><span style="color:#FF7B72">        add_header </span><span style="color:#E6EDF3">Strict-Transport-Security </span><span style="color:#A5D6FF">"max-age=31536000; includeSubDomains"</span><span style="color:#E6EDF3"> always;</span></span>
<span data-line=""><span style="color:#FF7B72">        proxy_pass </span><span style="color:#E6EDF3">http://unix:/var/www/myweb/myweb.sock;</span></span>

<p>In the above configuration, make sure you have changed it according to your requirements. One thing to look out for is the <code>server_name</code> directive. If you are working with a domain name, make sure to replace it correctly. Another thing would be the paths that are mentioned in the configuration. Make sure all of the mentioned paths in your correct according to your settings.</p>
<p>Save the file and enable this nginx project by creating its soft link at <code>sites-enabled</code> directory:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">ln </span><span style="color:#FF7B72">-</span><span style="color:#E6EDF3">s </span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">etc</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">nginx</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">sites</span><span style="color:#FF7B72">-</span><span style="color:#E6EDF3">available</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">myweb </span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">etc</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">nginx</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">sites</span><span style="color:#FF7B72">-</span><span style="color:#E6EDF3">enabled</span><span style="color:#FF7B72">/</span><span style="color:#E6EDF3">myweb</span></span></code></pre></figure>

systemctl restart nginx

For the final test, visit the <code>/admin</code> page to make sure the static files are also served correctly from our nginx service:</p>
